# 라벨 만들기

`labels.html`은 상품홈과 같은 Firebase 로그인으로 `productCatalogPrivate/products_v5`를 GET만 한다. 상품·재고·택요청·인쇄수량을 저장하는 경로는 없다. 읽은 자료에서 이름·바코드·라벨용 표기만 추리고 원가·매입가·구매 내역은 화면, Worker, 저장소로 넘기지 않는다.

칸 클릭, 사각형 끌기, Shift 범위, 키보드 선택, 시작칸/수량, 앞칸 잠금, 여러 장, 되돌리기를 지원한다. 입력한 라벨 값과 배치는 현재 문서 메모리에만 있다. 실물 인쇄 뒤 누르는 ‘마지막 쓴 칸 기억’만 브라우저 저장소에 칸 번호와 시각을 남긴다. 저장소를 쓸 수 없어도 작업할 수 있다.

## 같은 인쇄 도안

`assets/labels/engine/rlkit.py`와 `make_round_label_offset.py`는 2026-11-21 round_label_v6 정본 사본이다. `SOURCE.json`에 원본 해시가 있다. 브라우저 Worker의 Pyodide 0.29.0에서 원래의 글꼴 윤곽선·Shapely 자동배치·ReportLab5.1.0을 실행한다. 순수 Python wheel은 자체 제공하며 Pyodide 고정 버전과 패키지는 jsDelivr에서 불러온다. 초기 실행은 다운로드 시간이 들 수 있으며 이후 Worker 안에 글꼴과 도안을 재사용한다. 각 파일은 페이지 빌드 버전으로 캐시를 구분한다.

`browser_bridge.py`는 UI의 빈칸을 보존해 A4에 배치하는 어댑터다. 원래 `solve`/`draw_label`은 바꾸지 않는다. 중심은 왼쪽15.70mm·위24.15mm, 피치22.5mm, PP7108 9열×12행이다. 바코드를 새로 배정하는 기능은 없으며 입력된 EAN-8 확인 숫자를 검사한다. 재질·제조국 등 필수 표기가 비면 인쇄를 막고 페이지 안에서만 수정하도록 한다.

PDF.js4.10.38가 만든 PDF를 그대로 화면에 그린다. ZXing0.21.3이 PDF를300dpi로 렌더해 배치한 칸마다 EAN-8을 다시 읽는다. 읽히지 않은 칸이 있으면 다운로드를 활성화하지 않는다. 외부 판독 도구가 전혀 로드되지 않는 경우에는 지원하지 않는다고 표시한다. PDF에는 선택용 원, 칸 번호, UI가 들어가지 않는다. ‘PDF 열어 인쇄’는 같은 Blob을 브라우저 PDF 보기로 연다.

## 표기 보완

`src/labels-specs.json`은 기존에 확인된 라벨의 바코드별 재질·국가·판매원 표기 규칙이다. 공개 상품 장부나 원가 자료를 넣지 않는다. 현재 상품 목록은 로그인 후에만 읽는다. 상품홈 떡메모지 부모의 컴퍼니 옵션은 이미 확인된20000776을 화면용 선택지로만 제공한다. 빼꼼·부적은2027/2057에 확정된 라벨 품명을 사용한다. 상품홈 자체는 수정하지 않는다. 확인되지 않은 표기는 자동 추측하지 않고 입력을 요구한다.

## 확인

`python build.py`, `node --test tests/labels.test.cjs`, 기존 `node --test tests/*.test.cjs`를 실행한다. 브라우저 검수는 Tutti browser로 격리된 로컬 가상 상품 목록을 사용한다. 116칸(6/6/2/2/100)을 만든 PDF가2057 정본과400dpi 픽셀 동일·위치차이0mm이며 zbar·ZXing116/116을 통과했다. 시작107번에서5칸은 앞106칸을 비우고 두 장으로 이어진다. 재질 누락9칸의 인쇄 차단, 이 문서에서만 수동 보완, 원가 미노출, GET만 사용,390px 선택·상품 입력, 브라우저 저장소 차단도 검수한다.

폰에서는 칸 선택·상품 입력·PDF 확인이 가능하다. 프린터 설정은 PC에서 엡손·PP7108·매트·높음·실제크기100%·여백없음해제로 맞춘다. 인쇄를 자동으로 했다고 기록하거나 상품 수량을 차감하지 않는다.
